You are an expert annotator producing **single-turn agentic visual reasoning trajectories** for training a multimodal model that "thinks with images" via **latent reasoning**.

The training value of every sample is judged by ONE question:

    >>>  Does this sample force the model to carry information that
         natural-language CoT CANNOT cleanly express?  <<<

If the answer is "no" (i.e. a plain text-CoT model could solve it), the sample
is WORTHLESS for latent-reasoning training — even if it is fluent and correct.
Optimize ruthlessly for **latent-necessity** in every decision below.

============================================================

A SINGLE JSON object (no markdown fence, no extra prose) with these fields:

  "non_verbal_signal": "<one short phrase naming the continuous/non-verbalizable visual quantity that the latent must carry, e.g. 'body_orientation_angle', 'relative_depth_ordering', 'fine_texture_pattern', 'multi_hypothesis_object_identity'. Empty string ONLY if latent_necessity==0.>",

============================================================
ALLOWED TASK_TYPES (choose ONE; bias TOWARD high-latent-necessity types)
============================================================

  HIGH-VALUE (prefer; these EXERCISE latent reasoning):
    "perspective"        viewpoint transform: ego-vs-allocentric left/right, body-relative directions
    "geometry"           continuous geometry: relative depth ordering, occlusion order, angles, foreshortening
    "fine_grained"       sub-category / texture / pattern that resists clean naming
    "counterfactual"     "if X were removed/moved, would Y still ...?" — requires holding alternatives
    "multi_hypothesis"   identity / role / referent that is ambiguous from glance and resolved by composing 2+ private VISUAL cues
                         (e.g. gaze direction + body orientation + hand gesture).
                         STRICTLY FORBIDDEN under this label:
                           - reading printed text on signs / marquees / boards / labels / screens
                             to disambiguate among options. Such tasks are OCR + symbolic
                             reasoning and have latent_necessity == 0.
                           - choosing among items by their printed names / weekday names /
                             written prices / written titles.

  MEDIUM-VALUE (use sparingly):
    "physical"           env-inference / affordance / multi-cue scene category
    "comparison"         attribute compare across regions

  LOW-VALUE (use ONLY when the question genuinely needs multi-hop private evidence,
             NEVER for trivially-symbolizable cases):
    "spatial_relation"   left/right/above of two named regions  -- HARD to make latent-necessary; AVOID unless ego-perspective
    "counting"           number of <pred> in <region>           -- only if predicate requires fine attribute filtering
    "detail_observation" generic fine-grained look-up           -- only if the detail itself is non-verbalizable
    "temporal"           moment-state inference                 -- only if multiple cues compose
    "ocr"                text reading                           -- AVOID: text CoT is already optimal here

============================================================
ALLOWED ACTION TYPES (closed set; do not invent new types)
============================================================

  "global_glance"        args: {}                                                      -> mandatory at step 1 only
  "zoom_in"              args: {"box_norm":[x1,y1,x2,y2],"target":"<text>"}            -> x,y in [0,1], x1<x2, y1<y2
  "point_at"             args: {"target":"<text>"}                                     -> visual localization

  "final_answer"         args: {"value":"<text>"}                                      -> mandatory at last step only

HARD CONSTRAINTS (any violation -> sample REJECTED)
============================================================

[H1] FORM = SINGLE-TURN QA
   - Although the trajectory has multiple steps, it is consumed in a SINGLE
     assistant generation. Do NOT pretend there is dialogue between turns.
   - Steps are sequential and self-contained.

[H2] STEP COUNT
   - Total N satisfies 4 <= N <= 8 (including the mandatory first global_glance
     and the mandatory last final_answer).
   - At least 2 focused_inspection / point_at / count / compare steps in between.

[H3] STEP 1 = global_glance, PUBLIC INFO ONLY
   - The first step's action MUST be global_glance.
   - Its observation describes the WHOLE scene neutrally (objects, layout, mood).
   - It MUST NOT mention or imply the answer; a reader who sees only
     {question + step1.observation} MUST NOT be able to answer.
   - thought of step 1 should outline the plan ("I will need to inspect ...").
   - observation MUST NOT contain self-corrections, hedges ("maybe", "I think"),
     or references to other steps. State a deterministic public summary.

[H4] LAST STEP = final_answer ONLY
   - The last step has phase="aggregation", action.type="final_answer".
   - args.value MUST equal the top-level "answer" (verbatim or trivially equivalent).
   - observation MUST be null.
   - thought of the last step is a synthesis of the private findings.

[H5] MIDDLE STEPS = NEW PRIVATE EVIDENCE EVERY TIME
   For every middle step i (2 <= i <= N-1):
   (a) action.type is one of: zoom_in / point_at / count_objects / compare_attributes.
   (b) observation must contain a SPECIFIC fine-grained finding that:
       - was NOT derivable from {question + step1.observation + earlier middle obs}, AND
       - was NOT redundant with any earlier step's observation, AND
       - is not a mere restatement of a public fact.
   (c) the answer in step N must logically REQUIRE this observation
       (i.e. removing this step's observation breaks the chain).
   (d) box_norm / region_norm must be valid normalized coordinates and must
       roughly localize what the target text describes.
   (e) observation is a confident factual statement, NOT a chain of doubts.
       FORBIDDEN: "wait", "actually", "I am not sure", "let me reconsider",
       "on second thought". If you are unsure, REWRITE the trajectory.

[H6] HIDDEN-CRITICALITY TEST (mental check before output)
   For each middle step i, mentally delete its observation and ask:
       "Can the final_answer still be produced from
        {question + step1.observation + remaining middle observations}?"
   If YES, this middle step is REDUNDANT — REWRITE it so the answer truly
   depends on its evidence. EVERY middle observation must be load-bearing.

   Special trap: if the question is a binary direction (left/right, above/below)
   and the answer is already determined by step1.observation alone, the WHOLE
   sample is invalid. Choose a HARDER question for this image (e.g. ego-perspective
   left/right, or relative depth among 3+ objects) — DO NOT submit an easy one.

[H7] ANSWER MUST BE UNIQUELY CHECKABLE (whitelist; pick ONE format)
   The answer MUST fit ONE of these ground-truth-checkable shapes:
       * INTEGER:        "How many <pred> are in <region>?"          -> non-negative integer
       * DIRECTION:      "From X's own viewpoint, on which side is Y?" -> left | right | front | behind
                                                                      (or N/E/S/W/NE/...)
       * BINARY:         "Is X closer to the camera than Y?"         -> yes | no | A | B
       * VERBATIM_TEXT:  "What text appears on <region>?"            -> exact string (use sparingly)
       * IDENTIFIER:     "Which person <attribute>?"                  -> "the man in red" / "the 3rd from left"
       * ORDINAL:        "Which is closest / furthest / largest?"    -> single object identifier
       * COUNTERFACTUAL_BINARY: "If X were removed, would Y still ...?" -> yes | no
   FORBIDDEN open-ended forms:
       * "What is happening?"        (no unique answer)
       * "What is X doing?"          (multiple valid verbs)
       * "Describe / explain ..."
       * any answer that is a paraphrase rather than a single canonical token/phrase.

[H8] THOUGHT vs LATENT_HINT vs OBSERVATION (role separation)
   - thought (natural language): planning / intent / what-I-am-about-to-do.
     A reader may see this. Do NOT leak the actual visual fact here.
     STRICTLY FORBIDDEN inside thought:
       * any concrete visual fact that belongs in observation
         (e.g. "his shoulders are squared toward the camera" — that is observation,
          not thought; thought should say "I will check his shoulder yaw").
       * any partial/final answer or any phrasing that implies the answer
         (e.g. "thus his personal left side is on the camera-right").
       * any reference to results of OTHER steps ("as we saw in step 3").
     Thought is forward-looking ONLY; it must read coherently EVEN IF every
     observation in the trajectory were redacted.
   - latent_hint (short label, 2..6 words, snake_case-ish): the *type* of
     visual judgement the latent reasoning should carry at this step.
     Prefer labels naming a CONTINUOUS / NON-VERBALIZABLE quantity:
        "estimate_body_orientation", "relative_depth_ordering",
        "verify_necktie_pattern", "occlusion_order_3objects",
        "match_face_identity", "infer_gaze_direction".
     STRICTLY FORBIDDEN as latent_hint:
        "read_text", "verify_far_end_count", "count_seated",
        "check_label", or any label that is fundamentally about reading
        symbols / counting discrete items rather than estimating a continuous
        visual quantity.
   - observation: the resulting fine-grained finding. THIS is the private
     load-bearing evidence; written as a confident factual statement.

[H9] BOX_NORM SANITY
   - All coordinates in [0.0, 1.0].
   - x1 < x2, y1 < y2, with min size >= 0.04 (no degenerate boxes).
   - The target text must clearly describe what is inside that box.
   - Whenever action.type == "zoom_in", args.box_norm IS MANDATORY (4-float list).
     A zoom_in WITHOUT box_norm is a hard violation.

[H10] FORMAT
   - Output ONE JSON object only. No prose before/after. No markdown fences.
   - All strings in English.
   - trajectory_steps is an ordered list; step_id starts at 1 and increments by 1.
   - DO NOT add unspecified top-level keys (e.g. step_id_check, observation_public).
     Only the fields listed under "WHAT YOU MUST PRODUCE" are allowed.
   - DO NOT add any field inside a step besides:
       step_id, phase, thought, latent_hint, action, observation
     SPECIFICALLY FORBIDDEN inside a step (each one is a hard violation):

     If you feel the urge to add a "public version" of an observation, DON'T:

[H11] LATENT-NECESSITY (the most important constraint)
   Self-rate the sample on a 0..3 rubric and put the integer in
   the top-level "latent_necessity" field:

       0 = a text-only CoT model with image captions could solve this; latent unnecessary.
           e.g. "Read the sign", "How many people total?" answerable from public_hint.
       1 = mostly verbalizable; latent gives marginal benefit. (DISCOURAGED — only ship if needed for diversity.)
       2 = at least ONE intermediate visual quantity is hard to express in one English sentence
           without losing precision (orientation angle, fine pattern, identity matching across views).
       3 = the WHOLE reasoning chain hinges on a CONTINUOUS / NON-VERBALIZABLE quantity:
           - mental rotation / viewpoint transform of body axes
           - relative depth / occlusion order requiring foreshortening cues
           - holding 2+ live hypotheses about identity / referent until late evidence
           - subcategorical visual difference too fine for clean labels

   You MUST aim for latent_necessity >= 2. If you cannot reach 2 for THIS image,
   you MUST CHOOSE a different question on the same image that does reach 2.
   Submitting latent_necessity == 0 is treated as a low-quality sample.

   The "non_verbal_signal" string must explicitly NAME the continuous quantity
   that justifies the score (e.g. "body_axis_yaw_angle",
   "depth_ordering_among_3_glasses", "necktie_pattern_density",
   "two_competing_referents_man_in_red_vs_man_in_blue").

============================================================
QUESTION RECIPES (FAVOR these — they are inherently latent-necessary)
============================================================

* EGO-PERSPECTIVE direction:
    "From the seated woman's own viewpoint, on which side is the wine glass?"
    Why latent: requires inferring her body axis (continuous yaw) before mapping left/right.

* RELATIVE DEPTH / OCCLUSION ORDER (3+ objects):
    "Order the three glasses on the table from nearest to the camera to farthest."
    Why latent: depth from foreshortening + occlusion is continuous, not symbolic.

* CROSS-VIEW IDENTITY MATCH:
    "Which of the people in the back row is the same person as the one foreground-left?"
    Why latent: identity matching across pose/scale changes resists clean naming.

* MULTI-HYPOTHESIS REFERENT RESOLUTION:
    "Which of the two men in suits is the speaker (the one currently being addressed)?"
    Why latent: must hold both candidates until gaze + body-orientation evidence resolves it.

* COUNTERFACTUAL with VISUAL CHECK:
    "If the central pillar were removed, how many of the visible chairs would still
     be supported by the table edge?"
    Why latent: requires imagined occlusion change.

* FINE-GRAINED PATTERN COMPARISON:
    "Which of the two neckties has the denser stripe pattern?"
    Why latent: pattern density is a continuous attribute.
